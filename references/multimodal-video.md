# 视频资料的多模态处理

处理任何视频前必读。字幕会丢公式和图,补救办法是抽关键帧交给视觉通道;多模态调用贵,先分档再动手。

## 0. 原件优先

有官方幻灯片 / 讲义可下载时,先抓原件,公式与图以原件为准——从视频帧重建一份本可下载的 PDF 是浪费。视频消化只用于两种情况:课程没有公开幻灯片;或内容只存在于视频里(口头讲解、板书、现场演示)。

## 1. 成本三档

- **筛选档(规划期,默认)**:元数据 + 字幕之外,均匀采 3-5 帧看内容形态(幻灯片 / 板书 / 录屏),判断质量即可,成本可忽略。
- **按需档(学习期答疑)**:用户的问题指向某视频某处时,取该时间戳前后一两个关键帧再作答。不为一个问题消化整个视频。
- **全量档(仅限核心资料)**:每个主题最多一两个主干视频做完整消化,产物缓存进 `videos/<name>/` 并 commit——成本只花一次,之后复用。

不要通读 keyframes/ 全目录;按上面分档取用。

## 2. 全量消化流程

1. 建档与抽帧:`python scripts/learning_skill.py video <repo> --title ... --source ... [--mode scene|interval]`。幻灯片课用 scene(场景检测);板书类场景检测不可靠,用 interval(约 30 秒)。
2. 字幕:有官方字幕用官方;没有时在脚本外用 whisper 系转写,通过 `--transcript` 传入。
3. 关键帧去重:相邻近似帧只留一张(零依赖环境下由 agent 目检挑选)。一小时幻灯片课通常剩几十张。
4. 视觉通道阅读关键帧,写 visual-notes.md:公式尽量转写为 LaTeX;架构图说明节点、箭头、数据流、模块关系;代码说明文件、函数、输入输出与运行结果。不确定处标注"画面不清晰 / 需人工确认"。
5. 按时间戳把帧与字幕段对齐,合成 multimodal-summary.md。公式转写进文本的意义:多模态成本只在消化时花一次,之后答疑用纯文本检索即可命中,不必反复看图。
6. 未决问题写 questions.md;视频加入 resources.md(注明所属阶段与入选理由)。

## 3. 何时必须开视觉通道(按需档与全量档内)

画面含公式推导或板书;含架构图、流程图、系统图;含代码编辑器、终端、实验界面;含图表曲线;字幕有识别错误;讲解依赖手势或画面变化。人文社科类视频的视觉通道通常只做辅助。

## 4. 字幕与画面冲突

保留差异,不强行合并。在 multimodal-summary.md 中写明:字幕说了什么、画面显示了什么、当前更可信的判断、需要用户确认的地方。

## 5. 适用边界

幻灯片课效果最好;板书与手写识别率明显更低,对低置信段落加标注,避免 agent 拿着错读的公式自信作答。DRM 或登录墙后的视频抓不到;下载是否合规由用户对照平台条款确认。
